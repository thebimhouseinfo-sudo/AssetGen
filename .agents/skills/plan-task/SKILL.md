# plan-task

## Procedure
1. For Git projects check `harness/common/branch_authority.py status` before choosing any development/integration target; never guess `main`, and stop if policy is missing. Read approved CRITERIA and the Implementation Plan/GOALMAP and confirmed use class, actual scale, trust boundaries, proportionate safeguards and explicit exclusions.
2. Choose one approved Implementation Plan GOAL (observable outcome with linked CRITERIA IDs) and simplest implementation that meets its measurable acceptance and safety constraints; no speculative enterprise hardening or future-market infrastructure.
3. Define scoped tasks and tests with concrete prerequisites; mark out-of-scope "nice to have" as suggestions, not must-pass.
4. Detect OPEN/STALE gaps and overengineering **and** underscoping for approved commercial/market scale.
5. Submit to Reviewer for goal/scope fidelity. Present the human a compact result/non-goals/risks summary, not a required technical diff or P1/P2/P3 deep dive.

## Output
Actual evidence, limitations and next authorized action. Never silently change approved theory.
